# Методичка: табличная нейросеть для выбора стратегии кэширования

## 1. Постановка задачи
В веб‑сервисе электронных книг данные различаются по характеру обновления и доступности:
- **Статичные**: тексты книг, обложки.
- **Средней изменчивости**: категории, подборки, агрегированные рейтинги.
- **Динамические**: история чтения, закладки, персональные рекомендации.

Нужно классифицировать объекты данных по двум целям:
- **CachePlacement**: `EMBEDDED`, `SIDECAR`, `MULTI_LEVEL`.
- **DataVolatilityClass**: `STATIC`, `MEDIUM`, `DYNAMIC`.

Затем на основе предсказаний выдавать рекомендации по параметрам кэширования.

## 2. Таксономия классов
### 2.1 CachePlacement
- **EMBEDDED** — кэш в процессе приложения (минимальная задержка, ограниченный размер).
- **SIDECAR** — внешний распределённый кэш (масштабирование, общий доступ).
- **MULTI_LEVEL** — сочетание локального и распределённого уровней.

### 2.2 DataVolatilityClass
- **STATIC** — редкие обновления, длительное время жизни данных.
- **MEDIUM** — умеренная частота обновлений.
- **DYNAMIC** — частые изменения, требования к свежести.

## 3. Входные признаки
Табличный формат (CSV/Parquet), строка = тип объекта данных. Примеры признаков:
- `object_type` (категория объекта).
- `avg_size_bytes`, `p95_size_bytes`.
- `read_qps`, `write_qps`.
- `update_interval_sec`.
- `fanout_services`.
- `staleness_tolerance_sec`.
- `recompute_cost_ms`, `db_latency_ms`.
- `is_user_specific`, `is_shared_globally`.
- `consistency_required`.
- `peakiness`.

## 4. Модель
### 4.1 Архитектура
- Категориальные признаки → **embeddings**.
- Числовые признаки → **стандартизация**.
- Общий MLP‑backbone + две головы классификации:
  - голова CachePlacement
  - голова DataVolatilityClass

### 4.2 Обучение
- Оптимизатор **Adam**.
- **Early stopping** по macro‑F1 на валидации.
- **Class weights** для дисбаланса классов.

## 5. Метрики
- Accuracy и macro‑F1 по каждой голове.
- Матрицы ошибок (confusion matrix).

## 6. Рекомендации по кэшированию
Rule‑based маппинг от `(CachePlacement, DataVolatilityClass)` к параметрам:
- TTL (sec)
- Consistency
- Write strategy
- Eviction policy

Далее можно расширить до multi‑task регрессии.

## 7. Бейзлайн и интерпретируемость
- Бейзлайн: логистическая регрессия (One‑Hot + StandardScaler).
- Интерпретируемость:
  - permutation importance для бейзлайна
  - feature ablation для нейросети

## 8. Мини‑демо
Если нет реальных данных, можно сгенерировать синтетический датасет (200–500 строк),
используя логические зависимости:
- большие статичные объекты → чаще `SIDECAR/MULTI_LEVEL` и `STATIC`
- user_specific с частыми обновлениями → `EMBEDDED/MULTI_LEVEL` и `DYNAMIC`
